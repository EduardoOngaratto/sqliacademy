Introdução ao SQL Injection

O que é

SQL Injection é uma vulnerabilidade em que dados fornecidos pelo usuário acabam sendo interpretados pelo banco de dados como parte de um comando SQL. Em vez de serem tratados apenas como um valor a ser procurado ou gravado, esses dados passam a alterar a própria consulta.

A falha não está no banco de dados nem na linguagem SQL, e sim na forma como a aplicação monta a consulta. Quando o programa junta, em um único texto, o código SQL escrito pelo programador e o valor digitado pelo usuário, o banco recebe tudo misturado e não tem como saber onde termina o comando e onde começa o dado.

Por que acontece

Imagine o sistema de uma biblioteca que busca livros pelo nome do autor e monta a consulta concatenando o valor digitado:

String sql = "SELECT titulo, ano FROM livro WHERE autor = '" + autor + "'";

Com o valor Machado de Assis, a consulta funciona normalmente. Mas, ao buscar a autora D'Ávila, o texto montado fica assim:

SELECT titulo, ano FROM livro WHERE autor = 'D'Ávila'

O apóstrofo do nome fecha o texto antes da hora, e o que sobra (Ávila') deixa a consulta com erro de sintaxe. Ninguém atacou o sistema: um valor legítimo mudou a estrutura do comando. Se um valor inocente consegue quebrar a consulta, um valor escrito de propósito consegue alterá-la de forma calculada. Esse é o problema central do SQL Injection: código e dados misturados no mesmo texto.

Impacto

Como o atacante passa a escrever uma parte do comando, o estrago depende do que o banco permite à aplicação. Em geral, ele pode ler dados que não deveria (dados pessoais, senhas, informações financeiras), burlar a autenticação e alterar ou apagar registros.

As consequências vão além da parte técnica: vazamento de dados de clientes, prejuízo financeiro, danos à reputação da empresa e responsabilização legal. No Brasil, a Lei Geral de Proteção de Dados (LGPD, Lei nº 13.709/2018) prevê sanções para incidentes de segurança que envolvam dados pessoais.

Relevância

O SQL Injection é conhecido desde o fim da década de 1990 e continua presente em aplicações reais. O OWASP Top 10, principal referência sobre riscos de segurança em aplicações web, inclui na edição de 2025 a categoria A05:2025 – Injection, que reúne as falhas de injeção, entre elas o SQL Injection. No catálogo CWE, mantido pelo MITRE, essa falha é a CWE-89 (Improper Neutralization of Special Elements used in an SQL Command).

Ele persiste porque é fácil de introduzir: basta concatenar uma entrada em uma consulta. A boa notícia é que também é fácil de prevenir com técnicas bem conhecidas. Os próximos módulos mostram como reconhecer o código vulnerável e como corrigi-lo.
